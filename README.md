# 桌面 MMD 自设宠物

一个跑在桌面上的透明背景 MMD 看板娘：支持切换角色/场景、跳舞、点击互动、语音合成，
以及接 LLM 实现按天记忆的对话功能。

- **作者**：安运
- **版本**：0.1.6
- **GitHub**：https://github.com/anyunji666/DesktopPet

## 运行

开发环境（需要先装 [Node.js](https://nodejs.org/)）：

```bash
npm install
npm start
```

Windows 用户也可以直接双击根目录下的 `start-windows.bat`（首次会自动装依赖）；
之后日常启动用 `启动宠物.vbs`（后台静默运行，不弹命令行窗口）。
macOS / Linux 用户运行 `bash start-mac-linux.sh`（ZIP 解压后没有执行权限，用 bash 运行即可）。

## 目录说明

- `Character/`：角色模型（.pmx）及配套语音、台词、骨骼屏蔽等配置
- `Scene/`：可选的背景场景，背景调整方法见 `Scene/背景调整说明.md`
- `Actions/`：动作/舞蹈动画文件
- `main-modules/`：Electron 主进程，按领域拆分（配置、聊天记录、LLM、窗口菜单等）
- `public/`：渲染进程页面与前端逻辑

## 自定义素材

三样东西都是「把文件夹放进对应目录」就行，不用改代码。

| 想加什么 | 放到哪里 | 生效方式 |
| --- | --- | --- |
| 角色 | `Character/<角色名>/` | 重启程序 |
| 场景 | `Scene/<场景名>/` | 右键 → 🌄 切换场景 → 🔁 重新扫描场景 |
| 舞蹈 | `Actions/<舞蹈名>/` | 右键菜单里选择（没出现就重启一次） |

文件夹名就是菜单里显示的名字。

### 一、添加角色

1. 在 `Character/` 下新建一个文件夹，名字就是角色名。
2. 把模型的 `.pmx` 和它的贴图**原样**拷进去，别改贴图的相对路径。
3. 重启程序，右键菜单里就能切换到这个角色。

```
Character/
└─ 角色名/
   ├─ 模型.pmx          ← 必需
   ├─ 贴图文件 / tex/    ← 必需（模型引用的贴图）
   ├─ quotes.json        ← 可选：点击时的气泡台词
   ├─ voice/             ← 可选：点击时播放的语音
   ├─ persona.json       ← 可选：LLM 聊天人设
   ├─ assets.json        ← 可选：角色与用户的资产配置（右键菜单编辑，自动生成）
   ├─ fixes.json         ← 可选：材质修正
   ├─ lights.json        ← 可选：按角色覆盖默认灯光
   └─ physics.json       ← 可选：物理微调（裙摆 / 袖口 / 头发一直抖时用）
```

> 一个文件夹里有多个 `.pmx` 时，程序会选**体积最大**的那个。想用别的版本，把多余的移走。

#### 可选文件说明

**quotes.json**：点击模型时随机冒一句。

```json
{ "color": "#7a5fd0", "lines": ["今天也上线啦?", "准备好就开始吧。"] }
```

也可以直接写成字符串数组 `["台词1", "台词2"]`，气泡用默认颜色。

**voice/**：放 wav / mp3 / ogg / m4a / flac / aac。语音文件名写成台词的开头（忽略标点），比如 `今天也上线啦.wav` 对应台词「今天也上线啦?」。也可以用 `1.wav`、`2.wav` 这种编号，会按顺序补给没匹配上的台词。

**persona.json**：接 LLM 聊天时用的角色设定，也可以在右键菜单「角色与音色设置」里直接编辑（世界背景、角色资料、别名、你的资料都跟随角色）。

```json
{ "system": "角色设定……", "storyBackground": "世界背景……", "aliases": ["别名"], "readerInfo": "你的资料……" }
```

**assets.json**：右键菜单「🧰 角色资产配置」里编辑，不用手写。分「角色」和「你（用户角色）」两份，各填资产（可变现金额 + 预计多久到账，其他类别 1 到 31 天；「现金类」资产的合计就是「账户资金」，到账天数固定 0，金额可为负代表透支，一条都没有时自动建一条「账户资金」）、负债（剩余本金、月供，剩余期数由程序按「本金 ÷ 月供」自动算）、月度收入（含每月几号到账）、月度支出、随身携带物（物品名称、数量、单位、备注，只写进提示词，不参与资金计算）。页面会算出每月结余，以及今天 / 一周以内 / 一月以内的账户可用资金（今天 = 账户资金；一周以内 = 今天 + 7 天内到账的其他资产；一月以内 = 今天 + 31 天内到账的其他资产 − 全部欠款，可为负）。保存后会作为 `<financial_status>` 写进 LLM 提示词，让 AI 知道双方有多少钱、几天能凑到多少，据此决定角色花钱的手笔和拒绝、冒险的底气。

资产会随故事时间自动推算：程序只读 AI 回复摘要里的「故事时间」，不让 AI 记账，钱的变动由你在页面上手动改。从「故事开始日期」（页面顶部可改，留空时第一次读到故事时间自动填上）起，收入在到账日加进列表里第一条现金类资产，月度支出和负债月供每月 1 日从它里面扣；负债每月还一期，账户资金不够就延期，还完后不再发给 AI；没填月供的负债只算欠款，不算进月度支出，也不自动还款。推算是现算的，不改存档，保存时以页面显示的那一天为新起点。两方都清空后保存会删除该文件（填了故事开始日期则保留）。

**fixes.json**：个别模型的材质在这里显示不对，按角色修正（字段都可选，写了才生效）。

```json
{
  "whiteDiffuse": ["脸", "眉毛", "牙齿", "舌头", "眼白"],
  "brightness": { "衣": 1.2, "发": 1.15 },
  "emissive": 0,
  "contrast": 1.06,
  "saturate": 0.95,
  "specular": { "*": 0.18, "发": 0.28, "颜": 0.06 },
  "shininess": { "*": 20, "发": 35 }
}
```

- `whiteDiffuse`：材质名数组，命中的材质漫反射恢复成纯白。适用「作者把脸部 diffuse 压成 0.75 灰」导致脸比身体暗一圈的情况。
- `brightness`：材质名 → 倍数，乘到漫反射上，1 不变、1.2 变亮 20%、0.8 变暗。适用「贴图本身就偏暗偏灰、材质参数又都是 1 无处可调」的情况（例如庄方宜的 `tex/衣.png` 平均亮度只有 101）。上限 8。
- `emissive`：统一缩放自发光，1 = 保持原样，0 = 关掉。three 的 MMDLoader 会把 PMX 的「環境色」×0.2 当成 emissive 加进去（`MMDLoader.js` 里写死的），那是一层不受光照影响的均匀灰，会把暗部抬起来、整片画面像蒙了层灰；设 0 之后对比度和饱和度都会明显回来（代价是整体稍暗一点，可以用 `brightness` 补）。
- `specular`：材质名 → 高光强度（0~1，按灰度值设到高光颜色上）。很多模型 `specular` 全是 0、`shininess` 是 1，three 里就完全没有高光，看起来「没有光泽」。
- `shininess`：材质名 → 光泽度（1~200，越大高光越集中、越像硬表面）。皮肤类建议 0.05 左右的小高光、头发 30~40、金属/角 40+。
- 上面三个「材质名 → 数值」的字段都支持 `"*"` 作为默认值，具体材质名优先于 `"*"`。
- `contrast` / `saturate`：这个角色的画面对比度 / 饱和度（CSS filter，1 = 不变，上限 3），不写 = 不调色。关掉 `emissive` 之后画面容易偏艳，就把 `saturate` 往 1 以下调。按角色生效，切换角色时自动换；以前 `index.html` 里那条全局滤镜已移除。
- 所有字段都是按角色生效的，各角色互不影响；材质名要和 PMX 里完全一致（控制台 `__phys` 那套查不了材质名，直接看 PMX 或用模型编辑工具）。

**lights.json**：按角色覆盖默认灯光，模型贴图偏暗时用它比改材质更自然（明暗关系不会被拉平）。

```json
{
  "ambient": { "color": "#ffffff", "intensity": 0.85 },
  "key": { "color": "#ffffff", "intensity": 1.6, "position": [3, 10, 6] },
  "back": { "color": "#ffe0e8", "intensity": 0.65 }
}
```

- 三项都可选，没写的沿用默认灯光（`public/modules/scene.js` 的 `DEFAULT_LIGHTS`：ambient 0.6 / key 1.2 / back 0.5）。
- `ambient` 抬高整体（也压平层次），`key` 是主光方向强度，`back` 是背后的补光/轮廓光。想「亮但立体」就多给 `key`、少给 `ambient`。
- 优先级：默认灯光 → 角色 `lights.json` → 当前场景 `scene.json` 的 `lights`（场景是刻意的氛围，压过角色设置）。
- 每次切角色 / 重启读取，改完不用重启整个程序。

**physics.json**：个别模型的头发、裙摆、袖口会一直抖，原因多半是这些刚体和手臂、大腿等碰撞体反复接触，或者本身没有回复力。这里按角色修正，所有字段可选，不写不影响任何角色。刚体名就是 PMX 里的刚体名，写成正则。

```json
{
  "noCollide": [
    { "bodies": "^裙_", "with": "^(左|右)(腕|腕1|ひじ|手首)$" },
    { "bodies": "^裙_", "with": "^(左|右)(足|足1|ひざ|足首)$" }
  ],
  "freeze": [{ "bodies": "袖", "when": "idle" }],
  "damping": [{ "bodies": "^裙_", "linear": 0.98, "angular": 0.98 }]
}
```

- `noCollide`：`bodies` 命中的刚体不再和 `with` 命中的刚体碰撞。碰撞过滤是按「碰撞组」做的，同组里没被 `with` 命中的刚体也会一起被排除（控制台会列出来）。
- `freeze`：命中的动态刚体改成跟随骨骼、不再模拟（直接消除抖动，代价是这部分不再摆动）。`when` 默认 `"idle"`。
- `damping`：覆盖命中刚体的线性 / 角阻尼（0~1）。
- `when`：`"idle"` 只在待机动画里生效，`"always"` 任何动作都生效；`noCollide` / `freeze` 默认 `"idle"`，`damping` 默认 `"always"`。待机动画只有头部在动，身体不动，所以待机时关掉碰撞不会穿模；跳舞等大动作默认保留碰撞，避免大腿穿过裙摆。

**不知道该写什么**：打开开发者工具 Console，用 `__phys` 实时试。`__phys.help()` 看命令；`__phys.find("裙")` 看刚体名和碰撞组；`__phys.noCollide("^裙_", "腕|手首")` / `__phys.freeze("袖")` 立刻看效果；点一下右键菜单「待机」或 `__phys.restore()` 会撤销所有试验；找到合适的组合后 `__phys.export()` 会打印一份可以直接存成 `physics.json` 的内容。

**新角色最少只要 pmx + 贴图**。台词、语音、人设不配也能跑；跳舞时脸发灰，再补 `fixes.json`。

### 二、添加场景

1. 在 `Scene/` 下新建文件夹，名字就是场景名。
2. 放进场景模型（`.pmx` / `.pmd` / `.glb` / `.gltf`）和贴图。
3. 右键 → 🌄 切换场景 → 🔁 重新扫描场景，不用重启。

```
Scene/
└─ 场景名/
   ├─ 场景.pmx       ← 自动选最大的模型作为本体
   ├─ Tex/           ← 贴图，按相对路径自动找到
   └─ scene.json     ← 可选，所有字段都能省略
```

- 只有 `.blend` 的文件夹会被跳过，需要先在 Blender 里导出成 `.glb`。
- 只有 `scene.json`、没有模型，就是纯「背景 + 灯光」场景，可参考 `Scene/示例-黄昏`。

#### scene.json 常用字段（全部可选）

```jsonc
{
  "displayName": "菜单里显示的名字",
  "background": "linear-gradient(180deg, #f08a2e 0%, #ffdf8f 100%)", // 任意 CSS 背景
  "backgroundImage": "bg.jpg",                                       // 或背景图
  "ground": { "color": "#e4e1dc", "radius": 150 },                   // 圆形地面
  "fog": { "color": "#ffdf8f", "near": 60, "far": 130 },             // 远处渐隐
  "lights": {
    "ambient": { "color": "#fff1dc", "intensity": 0.85 },
    "key":     { "color": "#ffdcb0", "intensity": 1.4, "position": [-6, 6, 6] }
  },
  "extras": [ { "file": "车辆.pmx", "position": [30, 0, -20], "rotationY": 90 } ]
}
```

其他模型默认忽略，要用就写进 `extras`。改完 `scene.json` 点「重新扫描场景」生效。

#### 鼠标调整背景

| 操作 | 作用 |
| --- | --- |
| Shift + 滚轮 | 缩放背景 |
| Shift + 拖拽 | 移动背景 |
| Ctrl + 滚轮 | 背景前后移动 |
| Ctrl + 拖拽 | 绕角色旋转背景 |

### 三、添加舞蹈

1. 在 `Actions/` 下新建文件夹，名字就是舞蹈名。
2. 放进动作文件 `.vmd`，有配乐的话一起放音频。
3. 所有角色共用这个动作池，不用按角色配置。

```
Actions/
└─ 舞蹈名/
   ├─ 动作.vmd          ← 必需
   ├─ 配乐.wav          ← 可选，支持 wav / mp3 / ogg / m4a / flac / aac
   ├─ Camera.vmd        ← 镜头文件，文件名含「镜头」「camera」「表情」的会被自动忽略
   └─ preferred.txt     ← 可选，见下
```

- 一个文件夹里有多个 `.vmd` 时，自动选**最大**的（镜头 / 表情文件除外）。
- 选错版本时，在文件夹里放 `preferred.txt`，内容写一行想用的 vmd 文件名即可。
- 有多个音频文件时，按 wav → mp3 → ogg → m4a → flac → aac 的优先级取第一个。

#### 小提示

- 动作需要模型带有对应的辅助骨骼（全ての親、グルーブ、足D、腕捩、手捩等），骨骼缺失或含义不同会导致动作变形。
- 动作文件的作者通常有使用条款（署名、禁止商用等），放进来前请看一下自带的 readme。

### 排查问题

按快捷键 `Ctrl + Shift + I` 打开原生开发者工具窗口 → Console：

- `[pet]` 开头的是角色 / 动作 / 场景的扫描警告（缺 pmx、json 格式不对等）。
- `[scene]` 开头的是场景模型的尺寸、顶点数。
- `[shader]` 开头的是着色器编译错误。
- `[pet][physics.json]` 开头的是物理微调的提示（刚体名没匹配上、同组被连带排除等）。
- 模型头发 / 裙摆 / 袖口抖动：见上面的 `physics.json` 说明和 `__phys` 调试命令。

### 安全说明

程序在本机开了两个只监听 `127.0.0.1` 的服务（页面静态服务、Gemini 轮询中转），并做了这些防护：

- **Host 校验**：请求的 Host 必须是本机地址 + 本服务端口，挡住 DNS rebinding。
- **Gemini 中转**：要求访问口令（自动生成，桌宠自己请求时自动带上，**不需要手填**）；拒绝浏览器发来的请求（带 `Origin` 的一律不处理）；限制请求体大小和请求频率；上游 Key 放在请求头里，日志里会脱敏。
- **静态服务**：只开放 `public` / `Character` / `Actions` / `Scene` 和 three.js 的必要目录，只读，且带 CSP。
- **窗口**：渲染进程沙箱化，禁止页面跳转到外部、禁止 `window.open`，权限请求默认拒绝（只放行麦克风）；IPC 只接受来自本程序页面的调用。
- **密钥**：API Key、中转 Key、语音服务密钥在 `config.json` 里用系统钥匙串加密存储（Windows DPAPI / macOS 钥匙串 / Linux libsecret）；设置界面只显示末四位（`••••abcd`），完整密钥不会传给页面。加密后的密钥只能在同一台电脑、同一个系统账号下解密，换机器需要重新填写。

设置里把 API Base URL 指向 `http://` 的**非本机**地址时，密钥会明文经过网络，请尽量使用 `https://`。
